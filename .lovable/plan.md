# Match the Current PDF to the Reference Print Form

## Confirmed comparison

- Both uploaded files are two-page A4 PDFs, but their document framing differs substantially.
- The reference uses a consistent bordered sheet area with approximately 15 mm side margins, a centered company heading, a right-aligned company logo, a compact grey `NOTE FOR APPROVAL` band, tightly aligned header rows, a three-column approver grid, and comments spaced vertically within the same frame.
- The current PDF loses the main frame around its opening content, uses inconsistent scale and spacing, and allows large saved rich-content elements to dominate pagination. Its approval grid is split awkwardly across pages and page two starts without the reference framing.
- The current PDF is generated by taking one continuous browser capture and slicing it into A4 pages. The slice calculation knows about rows and comment blocks but does not build complete reference-style page frames, footers, or watermark layers for each page.
- The saved Detailed Description contains rich text, tables, and images. Those values must remain unchanged; only their print sizing, containment, and page placement will change.

## Design-only changes

1. **Reproduce the reference A4 sheet geometry**
   - Use the reference page margins, content width, border weight, compact Arial typography, title height, logo placement, grey heading band, row heights, and cell padding.
   - Keep the company name centered independently of the logo so neither element shifts the other.
   - Preserve the existing dynamic company name, logo, NFA fields, description, approvers, and comments.

2. **Create stable PDF pages instead of slicing through the form**
   - Paginate the captured document at safe section boundaries so field rows, approver cells, images, and comment/version groups are not cut in half.
   - Give every generated page the same reference-style outer border and usable content area.
   - Continue overflowing content onto additional A4 pages without shrinking the complete document into an unreadable page.
   - Keep the exact existing data order; records with more content may use more pages than the reference.

3. **Constrain rich content without changing it**
   - Preserve all saved text, formatting, tables, and images.
   - Fit tables and images within the Detailed Description width, retain their aspect ratios, and prevent them from pushing the document outside the sheet.
   - Remove accidental print-only corner rounding and browser spacing so pasted content visually belongs inside the reference section.

4. **Match reference page furniture**
   - Add `ENFA No. <number> – <page> of <total>` at the bottom-right of every downloaded PDF page.
   - Add the large diagonal `DRAFT` watermark only while the NFA is not finally approved; omit it from completed/final PDFs.
   - Determine the watermark from the record’s existing status and pass that status only to the PDF presentation layer; do not alter approval logic or saved data.

5. **Keep all non-PDF behavior unchanged**
   - Do not change data loading, SAP calls, comments/version history, approval actions, permissions, DOCX data, uploads, or any other screen.
   - Keep the current PDF filename and Download PDF action.
